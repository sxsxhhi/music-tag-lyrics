## 2. 下一步行动 (Phase 1 修复规划)

1. 重构 `core/fetchers/lrc_red.py`：
   - 彻底分离“原始响应缓存 (`_raw_cache`)”与“本地音轨上下文验证 (`validate_candidate`)”；
   - 移除 `_cache[key] = None` 的破坏性负缓存；
   - 严禁使用本地字段回填远端对象，元数据缺失显式标记 `missing`；
   - 统一直查、match、search 的版本门禁与过滤规则；
   - 严控 `byModel` 与原生逐字可信度分级；
   - 引入规范的 `isrc_write_eligible` 判定字段。
2. 修复 `scripts/process_song.py`：
   - 封闭 ISRC 写入判定，要求双方 duration > 0 且 <= 3000ms，且必须 `isrc_write_eligible=True`；
   - 细化日志输出（区分歌词成功与 ISRC 写入状态）。
3. 验证 Phase 0 复现用例由红转绿，且现有 366 条回归测试保持全绿。
